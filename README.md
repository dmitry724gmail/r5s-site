# R5S — сайт и редактор мероприятий

## Что готово
Сайт с сохранёнными правками, раздел афиши из data/events.json, редактор Decap CMS по адресу admin/. Поля: фото, название, описание, начало/окончание, время, адрес, ссылка. Есть переключатели показа на сайте и автоматического скрытия прошедших событий. Даты завершения проверяются по московскому времени. Записи сортируются по дате начала.

## Что пока не подключено
Репозиторий GitHub и вход администратора. Файлы сами по себе не создают аккаунт или сервер авторизации. На публичном адресе панель честно покажет сообщение о необходимости подключения, пока настройки пустые.

## Публикация на GitHub Pages
1. Создайте публичный репозиторий и загрузите содержимое этой папки в его корень: index.html, admin, assets, data и .nojekyll. Загружайте распакованные файлы, не ZIP.
2. В репозитории откройте Settings → Pages → Deploy from a branch → main → /(root) → Save.
3. Дождитесь появления адреса сайта в Pages. Откройте его и раздел «Места и события».
4. В admin/settings.js заполните repo (владелец/репозиторий), branch и siteUrl (точный публичный адрес сайта, включая /имя-репозитория/, если он есть).
5. Подключите совместимый с Decap сервис GitHub OAuth. Инструкция: https://decapcms.org/docs/external-oauth-clients/ . Он должен предоставлять /auth и поддерживать протокол Decap. Создайте GitHub OAuth App с callback URL, который укажет выбранный сервис. Client secret хранится только в настройках сервиса авторизации.
6. В authServer укажите HTTPS-адрес этого сервиса. Секреты, токены и пароли в settings.js не добавлять.
7. Клиенту потребуется аккаунт GitHub с правом записи в этот репозиторий. Для приглашения: Settings → Collaborators. После принятия приглашения клиент сможет войти через /admin/.

Финальную авторизацию и публикацию нужно проверить на реальном репозитории. В этом архиве они не настроены: нет адреса репозитория и доступа к GitHub.

## Как клиент добавляет мероприятие
Открыть адрес сайта + admin/ → войти через GitHub → «Путеводитель 5 seasons» → «Мероприятия» → добавить элемент списка → загрузить фото и заполнить поля → включить «Показывать на сайте» → сохранить/опубликовать. Изменения появляются после завершения публикации GitHub Pages; это не мгновенное обновление.

Выключите «Показывать на сайте», чтобы скрыть запись. Для удаления удалите элемент списка и сохраните изменения. Все записи и фото в публичном репозитории доступны публично, включая скрытые записи. Для настоящих конфиденциальных черновиков требуется иная схема хранения.

## Проверка на компьютере
Установите Node.js и Python. В терминале из этой папки запустите `npx decap-server`, во втором терминале — `python -m http.server 8000 --bind 127.0.0.1`. Откройте http://localhost:8000/admin/ . Локальная панель редактирует файлы на компьютере; она не публикует их в GitHub. Проверяйте только на localhost. Зависимости CMS загружаются из интернета.

## Важно для переноса
Теперь это сайт из нескольких файлов. Одного index.html недостаточно для обновляемой афиши. Основные страницы и контакты сохраняются; SEO здесь не меняли.
